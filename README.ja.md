# OpenCode 統計表示ツール

OpenCode Desktop 2.0 の共有バックグラウンドサービスから統計を取得し、小さな Tk ウィンドウに表示する独立ツールです。共有サービス自体は起動せず、すでに稼働しているサービスを読み取ります。

## 起動方法

リポジトリのディレクトリで、次のコマンドを実行します。

```powershell
python opencode_stats.py
```

OpenCode Desktop を起動してから実行してください。サービス情報は `~/.local/state/opencode/service.json` から読み込み、`opencode:<password>` の Basic 認証で接続します。API リクエストのたびに登録ファイルの更新時刻を確認し、変更があれば URL と認証情報を読み直します。

## 表示項目と指標

### 実行状態

状態欄には「未接続」「生成中」「待機」を表示します。生成中かどうかは `session.execution.started` イベントと `/api/session/active` の実行状態を照合して判断します。step が終了しただけでは「待機」に戻しません。

SSE 接続が維持されていても統計の取得に失敗した場合は「取得エラー」と表示します。この表示中は、画面の統計が古くなっている可能性があります。対象セッションの情報を正常に取得すると解除されます。

### 実効速度（tok/s）

同一セッション・同一モデルについて、直近 10 回の応答速度を加重平均します。

```text
Σ(output + reasoning) / Σ(streamed - created)
```

計測時間には、モデルの応答区間である `time.created` から `time.streamed` までを使います。ツール実行や後処理の時間は含めません。

- `streamed` がない応答は平均に含めず、直近 1 回について `(completed - created)` で算出した参考値を橙色で表示します。
- 生成中のメッセージ、トークン数がないメッセージ、経過時間が 0.05 秒未満または 600 秒を超える応答は集計対象外です。
- 起動時、セッション切替時、`session.step.ended` の受信時に、`/api/session/{sid}/message?type=assistant&limit=20&order=desc` から履歴を取得します。履歴を古い順に処理し、最新モデルの正常終了 step を最大 10 件復元します。
- 古い応答は `(time.created, メッセージID)` の順で判定し、集計前に除外します。そのため、履歴の再取得やイベントの重複で平均値が変わりません。この判定は 15 秒ごとの定期取得にも適用します。
- 対象セッションまたはモデルが変わると、平均値をリセットします。

### その他の統計

- **last**: 直近 1 step の単発 tok/s と、計測区間（応答区間または完了区間）を表示します。平均値との照合やデバッグに使います。
- **キャッシュヒット率（累積）**: `read / (input + read + write) * 100` で算出します。`read` と `write` がともに 0 の場合は「未計測」と表示します。
- **キャッシュ read / write / input トークン数（累積）**: `/api/session/{sid}` が返すセッション累積 `tokens` をそのまま表示します。ツール側では独自に加算しません。
- **対象モデル・セッションタイトル**: 補助情報として表示します。セッションを切り替えると統計をリセットし、前のセッションの値は引き継ぎません。

## 操作方法

ウィンドウを右クリックすると、次の操作ができます。

- 統計を再取得する
- 対象セッションを選ぶ（自動追従または固定）。`parentID` を持つ子セッション（サブエージェント）には `[子]` を付けて表示する
- ウィンドウを常に最前面に表示する
- ウィンドウを閉じる

## 技術的な実装と制約

### API とイベント取得

OpenCode 2.0.30 の `/api/event`（SSE）を購読します。起動時、イベント受信時、15 秒ごとの定期取得で、次の API から情報を読み込みます。

- `/api/session`
- `/api/session/{sid}`
- `/api/session/{sid}/message`
- `/api/session/active`

`session.step.ended` を受信した場合は、表示対象のセッションに限ってセッション情報と最新 20 件の履歴を再取得します。同じ対象への未処理の同期要求は 1 件にまとめ、子セッション（サブエージェント）の step では再取得しません。単一メッセージの詳細取得 API と、再取得専用のタイマーは使いません。

OpenCode の時刻には、モデルリクエスト開始を示す `created`、応答ストリーム終了を示す `streamed`、後処理を含む完了を示す `completed` があります。`completed - created` にはツール実行時間も含まれるため、通常の速度計測には使いません。

API には `limit`、`order`、`type` を指定し、一覧やメッセージを全件取得しないようにしています。メッセージ履歴は `type=assistant&limit=20&order=desc` で最新 20 件に絞ります。

集計ではメッセージ ID と `time.created` を使って順序を判定し、重複や古い応答を除外します。履歴に複数のモデルが含まれる場合は、古い順に処理し、新しいモデルに切り替わった時点で平均をリセットします。最終的な平均には最新モデルの記録だけが残ります。

実行中のセッションに自動追従するときは、`/api/session/{sid}` の `parentID` を確認し、子セッションの実行では対象を切り替えません。親セッションを優先します。対象を固定している間は、固定したセッション以外の実行を無視します。

SSE のイベントフレームは `{"id", "type", "data": {sessionID, ...}}` の形式です。15 秒ごとに届く `: heartbeat` コメント行は破棄します。SSE は過去のイベントを再配信しません。接続が切れた場合は 2 秒後に再接続し、対象セッションの直近の確定値を取り直します。

### 通信の安全策とスレッド構成

HTTP 通信には Python 標準ライブラリの `urllib.request` を使い、接続先を制限しています。

- `service.json` に登録された URL のうち、scheme が `http` で、ホストがループバック（`localhost`、`127.0.0.1`、`::1`）のものだけに接続します。それ以外は未登録として扱い、停止します。
- リダイレクトは常に拒否します（`HTTPRedirectHandler.redirect_request` は `None` を返します）。
- 空の `ProxyHandler` を登録し、システムのプロキシ設定を使いません。

Tk のメインスレッドは画面描画とキューへの投入を担当し、HTTP 通信は SSE 読み取りスレッドと API ワーカースレッドで行います。同期・定期取得の結果は `target-stats` などの応答として、失敗は `sync-error` として画面スレッドに通知します。画面では失敗時に「取得エラー」を表示し、対象セッションから正常に取得できると解除します。

HTTP 401 を受信した場合は URL、認証情報、更新時刻のキャッシュを破棄します。次のリクエスト時に `service.json` を読み直します。

### 依存関係・テスト

外部パッケージは使わず、Python 標準ライブラリだけで動作します。通信先は既存のローカルサービスに限られ、秘密情報や会話本文を永続保存しません。

テストは次のコマンドで実行できます。計測ロジック、集計、API クエリ生成を検証し、外部通信は行いません。

```powershell
python -m unittest test_opencode_stats
```

コード量は、空行を含めて `opencode_stats.py` が約 694 行、`test_opencode_stats.py` が約 301 行です。
